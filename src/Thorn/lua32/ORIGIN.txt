  src/lapi.c, lstate.c, ldo.c, lundump.c, lvm.c, ltable.c, lgc.c,

Not copied (retail DllMain does not lua_strlibopen):
  src/lua/*, src/luac/*, src/lib/ldblib.c,
  src/lib/linit.c (that linit opens strlib)

lstrlib.c is compiled so liolib can link luaI_classend / luaI_singlematch.
lua_strlibopen is never called (same as retail DllMain).

lparser.c (the stock 3.2.2 recursive-descent parser + code emitter) is NOT
vendored here a second time: lparser_stub.c #includes the single shared copy
at src/luaprofile/lua32/src/lparser.c, so Thorn compiles the real luaY_parser
(text .thn / lua_dostring path). Retail thorn.dll carries this exact code at
0x06f526d0..0x06f54dd0 (init_state .. recfield; luaY_parser = FUN_06f52650),
so every function in that window maps 1:1 onto lparser.c; the tracker names
them by their lparser.c identifiers.

Thorn additions (not PUC-Rio):
  lparser_stub.c — one-line #include of the shared luaprofile lparser.c
  (historically a luaY_parser-errors stub, no longer)

Thorn alterations of PUC-Rio files (plainly marked):
  include/lua.h — LUA_VERSION "Lua 3.2" (retail FUN_06f51100); stock 3.2.2 was "Lua 3.2.2"
  src/llex.c — added #include <stdio.h> for MSVC sprintf
