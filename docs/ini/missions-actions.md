# Mission trigger actions (`Act_*`)

Reference for every action a `[Trigger]` section can contain. A trigger may hold any number of `Act_*` lines; they run in file order when the trigger's condition becomes true. Parameters are read **positionally** from the comma-separated values of the line by each action's `Parse` function.

## File location / how it is found

`Act_*` lines are keys inside `[Trigger]` sections of mission script files (see [missions.md](missions.md#file-location--how-it-is-found)); the files are opened through `OpenContentDataIni` relative to the Data path. Key names are matched case-insensitively against the factory table `GActFactory` ([MissionScript.cpp:143](../../src/Content/MissionScript.cpp#L143)); the classes are in [MissionAct.cpp](../../src/Content/MissionAct.cpp). Actions have no state in save games (a save only records which triggers are active, see [missions-saves.md](missions-saves.md)).

## Conventions

* Types and "label"/"nick" are explained in [missions.md](missions.md#conventions-used-in-the-tables) and [missions-conditions.md](missions-conditions.md#conventions). An **optional** value means the code tests `is_value_empty(i)` and keeps the constructor default when it is empty.
* "Quaternion W,X,Y,Z" values are normalised and converted to a matrix at load time; an all-zero quaternion is not guarded.
* Words listed for a value are the only ones the code compares (`stricmp`, case-insensitive unless noted); an unknown word silently keeps the default. There is no error message.
* Where a bool is described with the word "true", the underlying `get_value_bool` accepts exactly `true`/`1`/`false`/`0` (see [parsers.md](parsers.md)).
* Most actions return success even when their target does not exist; the cases that return failure (which only matters for the trigger bookkeeping) are not described.

## Nag actions

A "nag" is a mission-owned watcher object, keyed by its nag id, that plays NPC/NN voice lines while the player ignores an instruction. All nag processing is suspended while `Act_NagClamp` is `true`. `Act_NagOff` removes a nag. The two distance nags share one engine: when the player's ship is farther than `distance` from the target (an object's current position, or a fixed point), a 20 s timer starts; at each timeout, if the player has moved less than 900 units closer since the last check and is still farther than `distance`, a line (`nag_pos`, `nag_dst_ship`, `nag_dst_base`, `nag_dst_hole`, `nag_dst_gate`, `nag_dst_tl`, chosen from the target's type, with the speaker's voice) is played. Every finished nag comm spends one of 4 nags; when they are exhausted the mission is set to `FAIL` with the *fail text id*. The nag ends when the player docks with / enters the target (base, gate, hole or trade lane). If the speaker is flying in the player's formation no line is played.
