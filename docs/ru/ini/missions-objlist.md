# Директивы `[ObjList]` (задачи NPC)

Секции `[ObjList]` задают именованные списки директив ИИ (лететь туда, следовать за тем, стыковаться, ...), которые корабли миссии выполняют по порядку. Список привязывается к кораблю через `init_objectives =` в `[MsnShip]`, через `Act_GiveObjList` или `Act_SpawnShip`/`Act_SpawnShipRel`; именно его игра записывает обратно в сохранения как `[MObjective]`, когда корабль находится посреди сценария.

## Расположение файла / как он находится

Секции `[ObjList]` лежат в файлах скриптов миссий (см. [missions.md](missions.md#расположение-файла--как-он-находится)); тот же разборщик читает и секции `[MObjective]` сохранений ([missions-saves.md](missions-saves.md)). Загрузчик секции — `LoadObjList` ([MissionObjList.cpp:200](../../../src/Content/MissionObjList.cpp#L200)); каждая директива — это ключ секции, который позиционно разбирается методом `Parse` класса этой директивы. Имена ключей сравниваются без учёта регистра в порядке таблицы ниже ([MissionObjList.cpp:166](../../../src/Content/MissionObjList.cpp#L166)); неизвестный ключ молча пропускается.

Каждая директива хранит **всю исходную строку** (до 255 символов), чтобы её можно было записать обратно дословно.

## Соглашения

* Цели, названные в директиве (имена кораблей, соларов, метки, `Player`), разрешаются **в момент выполнения** в текущей системе корабля. Имя, которое не разрешилось, сразу завершает директиву (корабль переходит к следующей); ошибки нет.
* Значения «вида» (kind): `goto` (без флагов), `goto_no_cruise` (запретить круиз), `goto_cruise` (принудительный круиз). Любое другое слово трактуется как `goto`.
* Несколько чисел, которые могли бы быть float, читаются через `get_value_int` (разбор как у `atoi`), поэтому дробная часть **отбрасывается**: `GotoVec`, `Guide`, `GuideShip`, `Follow`, `Trail`, `Dock`, `StayInRange`/`StayOutOfRange` (сферическая форма). Там, где значение читается как float, это помечено `float`.
* Поля, которые классы op оставляют безымянными, показаны как `Field_xx`; их смысл в исходниках не задокументирован. Значения по умолчанию из конструкторов соответствующих записей op ([include/common_pub.h](../../../src/include/common_pub.h)) приведены там, где это уместно. Op директивы Goto проверяет `Field_50 >= 0` и `Field_64 >= Field_60`.
* Директива, задающая `priority` (см. `SetPriority`), использует его для всех последующих директив; если приоритет не задан, берётся приоритет корабля по умолчанию.

### Директивы зон (`StayInRange` / `StayOutOfRange`)

Общий разборщик `ParseZone` ([MissionObjList.cpp:974](../../../src/Content/MissionObjList.cpp#L974)). Пусть `i` — текущий индекс, начинающийся с 0.

1. Если присутствует значение 5: **форма-параллелепипед**. Значения 0..2 — минимум параллелепипеда (float), значения 3..5 — максимум (float); `i` становится 6.
2. Затем, если присутствует значение 3 (после параллелепипеда это всегда так): **сферическая форма** — значения `i`, `i+1`, `i+2` — центр (int), `i+3` — радиус (int); `i += 4`. Иначе **форма-объект** — значение `i` — имя объекта (47 символов), значение `i+1` — радиус (int); `i += 2`.
3. Если значение `i` присутствует и не истинно (`get_value_bool`), режим инверсии директивы ставится в 2 (иначе он остаётся 0 для `StayInRange` и 1 для `StayOutOfRange`).

На практике полезны строки `StayInRange = x, y, z, radius` и `StayInRange = object_name, radius`. Форма-объект требует, чтобы имя разрешилось в момент выполнения.

### Не читается из INI

У `FObjListTractorBeam` (тип директивы 0x19) и у номеров типов 0x17/0x18 нет ключа в INI; директива трактор-луча создаётся только движком.
