# Данные содержимого по системам и базам (Content.dll)

Эта страница описывает те части файлов систем и таблиц с фиксированными именами, которые читает `Content.dll` (исходники в `src/Content/`), чтобы наполнить звёздные системы и базы: зоны с настройками трафика и столкновений, джамп-гейты и торговые трассы, solar NPC, таблицы кратчайших путей между системами, базу данных миссионных баз (`mBases.ini`) и новости бара. Общее чтение тех же файлов систем модулями Common, Server и Client описано в [world-data.md](world-data.md); здесь перечислены только ключи, которые читает сам Content.

**Расположение файла / как он находится.** Файл системы — `Systems\<Xx##>\<Xx##>.ini` внутри каталога вселенной; имя задаёт ключ `file` секции `[system]` в `universe\universe.ini` (ключ `universe` секции `[Data]` в `freelancer.ini`, см. [freelancer-ini.md](freelancer-ini.md) и [world-data.md](world-data.md)). Сам Content этот путь не строит: он просит у сервера ридер на файл системы через `pub::BuildSystemReader` ([server_pub.cpp:349](../../../src/Server/server_pub.cpp#L349)) и просит обойти зоны через `pub::System::EnumerateZones` ([server_pub.cpp:6827](../../../src/Server/server_pub.cpp#L6827)). Все остальные файлы этой страницы имеют фиксированные имена и открываются через `OpenContentDataIni` ([ContentDataPath.cpp:17](../../../src/Content/ContentDataPath.cpp#L17)): имя присоединяется к каталогу Data (`data path` в `[Freelancer]` файла `freelancer.ini`). Грамматика, правила регистра, аксессоры `get_value_*` и двойственность текст/BINI описаны в [parsers.md](parsers.md); соглашения таблиц ключей (типы, «не проверяется», «побеждает первое определение», хэшированные id) те же, что в [ai-and-encounters.md](ai-and-encounters.md#соглашения-общие-для-всех-таблиц-ниже).

## 1. Порядок загрузки

| Шаг | Триггер | Что читается |
|---|---|---|
| Игровые таблицы | конструктор контроллера `GameSupport` | Таблицы с фиксированными именами из [ai-and-encounters.md](ai-and-encounters.md) и `missions\news.ini` (раздел 6). |
| Загрузка игры | сообщение `LoadGame` с ридером файла сохранения | `LoadDynBaseInfo` перестраивает таблицу баз и читает данные `[BaseFaction]` каждой базы из `missions\mBases.ini` (`BuildContentBases`, [BaseDB.cpp:415](../../../src/Content/BaseDB.cpp#L415)); `LoadDynSysInfo` перестраивает таблицу систем; просматриваются секции `[DynBaseInfo]` / `[DynSysInfo]` (раздел 7); затем таблицы путей (раздел 4). |
| Игрок входит на базу | сообщение `BaseEnter` (`FContentBase::Load`, [GameSupport.cpp:562](../../../src/Content/GameSupport.cpp#L562)) | Секции `[MVendor]`, `[GF_NPC]` и `[mRoom]` базы из `mBases.ini` (со счётчиком ссылок: читаются, когда входит первый игрок, и сбрасываются, когда выходит последний). |
| Система со столкновениями | сообщение `SystemLoaded` (`FSystemInfo::LoadFull`, [SystemInfo.cpp:365](../../../src/Content/SystemInfo.cpp#L365)) | Файл системы: solar NPC, `[EncounterParameters]`, `[Object]`, зоны с ключами популяции. |
| Система без столкновений | планирование маршрута и случайные миссии (`FSystemInfo::Load(false)`) | Тот же файл при выключенных столкновениях: только `[System]`/`[SystemInfo]`, `[Object]` и ключи зон, не относящиеся к блоку популяции. |

`FSystemInfo::LoadFromReader` ведёт счётчик ссылок: файл читается только при переходе 0 в 1.

## 2. `universe.ini` и файл системы: доля Content

`universe\universe.ini` читает модуль Common ([world-data.md](world-data.md)); Content открывает его ещё один раз, в `WriteSystemPathTables` (раздел 4), чтобы взять `nickname` каждой секции `[System]`. Из секций файла системы Content читает `[System]`/`[SystemInfo]`, `[EncounterParameters]`, `[Object]` и секции зон (тип `[Zone]`, как выбирает загрузчик Common); всё остальное (`[Music]`, `[Ambient]`, `[Background]`, `[Asteroids]`, `[Nebula]` и так далее) Content не интересует и описано в [world-data.md](world-data.md) и [client-world-fx.md](client-world-fx.md).

## 3. Файлы систем (вид со стороны Content)

### 3.1 `[EncounterParameters]`

Читается `FSystemInfo::LoadFromReader` ([SystemInfo.cpp:46](../../../src/Content/SystemInfo.cpp#L46)) только когда столкновения загружаются. Секция читается **позиционно**: первая строка со значением берётся как id столкновения, вторая — как имя файла, как бы ни назывались их ключи. По соглашению они записываются так:

```
[EncounterParameters]
nickname = example_enc_01
filename = missions\encounters\example_enc_01.ini
```

| Строка | Ключ (не проверяется) | Тип | Значение |
|---|---|---|---|
| 1 | `nickname` | id | Id столкновения: `CreateID(value 0)`. Зоны ссылаются на него через `encounter = id, level, chance` (раздел 3.4). |
| 2 | `filename` | string | Путь относительно пути Data (копируется в буфер из 259 символов). Файл открывается через `OpenContentDataIni`; если открыть не удаётся, секция молча пропускается. Формат: [ai-and-encounters.md](ai-and-encounters.md#3-файлы-параметров-встреч). |

Повторный id сохраняет свой слот и заменяет параметры. Объекты параметров живут только пока перечисляются зоны (зона копирует то, что ей нужно), поэтому изменение файла после загрузки системы не действует.

### 3.2 `[System]` / `[SystemInfo]`

| Ключ | Тип | По умолчанию | Значение | Источник |
|---|---|---|---|---|
| `local_faction` | string | группа 0 | Никнейм группы репутации локальной фракции системы. Допускаются оба написания заголовка, `[System]` и `[SystemInfo]`. | [SystemInfo.cpp:73](../../../src/Content/SystemInfo.cpp#L73) |
| `rpop_solar_detection` | bool | true | Читается только из `[SystemInfo]` (в `LoadSolarNpcs`, только в одиночной игре передаётся модулю случайной популяции): используются ли solar-объекты для обнаружения игрока при случайной популяции. | [SystemInfo.cpp:351](../../../src/Content/SystemInfo.cpp#L351) |

### 3.3 Секции `[Object]`: ключи solar NPC

Каждую секцию `[Object]` читают два независимых прохода.

**Проход A: джамп-гейты, джамп-холы и кольца торговых трасс** (`LoadFromReader`, [SystemInfo.cpp:114](../../../src/Content/SystemInfo.cpp#L114)). Ключи обрабатываются в порядке файла; **первый `archetype`, значение которого не одно из трёх распознаваемых слов, завершает секцию** (остальные её ключи не читаются, поэтому объект с другим archetype не записывается).

| Ключ | Тип | По умолчанию | Значение |
|---|---|---|---|
| `nickname` | string | 0 | Никнейм объекта, преобразуется через `GetNicknameId`. |
| `pos` | 3 floats | 0, 0, 0 | Позиция. |
| `rotate` | 3 floats | 0, 0, 0 | Углы Эйлера в градусах (значения 0, 1, 2 = x, y, z), преобразуются в матрицу поворота. |
| `archetype` | string | нет | `Trade_Lane_Ring`, `jumpgate` или `jumphole` (без учёта регистра). Остальные завершают секцию. Кольцо записывается с никнеймом, позицией, поворотом, `prev_ring`, `next_ring`, `reputation`; гейт или хол — как переход (тип 1 / 2) с `goto`. |
| `prev_ring`, `next_ring` | string | 0 | Никнеймы соседних колец. |
| `goto` | string system, string object | 0, 0 | Никнейм системы назначения (значение 0) и никнейм объекта назначения (значение 1). |
| `reputation` | string | в retail не инициализировано | Никнейм группы репутации кольца. |

**Проход B: solar NPC** (`LoadSolarNpcs`, [SystemInfo.cpp:311](../../../src/Content/SystemInfo.cpp#L311), ключи в [NpcCreate.cpp:23](../../../src/Content/NpcCreate.cpp#L23)). Solar-объект становится NPC, если у него есть `nickname` и хотя бы одно из: `behavior`, `base`, цель стыковки на самом объекте, `reputation` или `msg_id_prefix`.

| Ключ | Тип | По умолчанию | Значение |
|---|---|---|---|
| `nickname` | string | пусто | Никнейм объекта (не более 47 символов). |
| `base` | string | нет | Никнейм базы (`GetBaseID`); используется только первый ключ `base` секции. База уже должна находиться в таблице баз content. |
| `reputation` | string | -1 | Группа репутации, с которой связана репутация solar-объекта. |
| `pilot` | id | нет | Id личности пилота ([ai-and-encounters.md](ai-and-encounters.md#1-личности-пилотов-missionspilots_populationini-missionspilots_storyini)); применяется, только если такой пилот существует. |
| `behavior` | string | -1 | Имя графа состояний лидера из `AI\state_graph.db` (без учёта регистра); неизвестные имена дают -1, из-за чего NPC не получает состояние AI. |
| `msg_id_prefix` | string | пусто | Префикс сообщений комма (не более 63 символов). |

### 3.4 Секции зон (`Zones.cpp` и `Encounters.cpp`)

Для каждой зоны, которую обходит сервер, ридер ставится на секцию этой зоны, и `ParseSystemZone` ([Zones.cpp:150](../../../src/Content/Zones.cpp#L150)) читает её остаток. Ключи, которых он не знает, передаются парсеру популяции `FZonePopulation::ParseValue` ([Encounters.cpp:214](../../../src/Content/Encounters.cpp#L214)) (только когда столкновения загружаются) и в остальных случаях игнорируются. Ключи геометрии зоны (`pos`, `rotate`, `shape`, `size`, `property_flags` и так далее) относятся к Common ([world-data.md](world-data.md)).

| Ключ | Тип | По умолчанию | Значение / допустимые значения |
|---|---|---|---|
| `nickname` | string | нет | Id зоны, `CreateID(value 0)`. Важны два соглашения об именах (поиск подстроки, `strstr`, **с учётом регистра**): имя, содержащее `Tradelane`, у зоны, чей сохранённый код формы равен 3 (`BOX` в таблице форм Common) и чьи размеры по x и y оба более чем в десять раз меньше размера по z, помечает зону как зону торговой трассы; имя, содержащее `vignette`, помечает зону как законную (lawful). |
| `path_label` | string label, ints | нет | Метка пути патрулирования/торговли: значение 0 — id метки, значения 1.. — индексы путей (дубликаты удаляются, порядок первого появления). Тогда зона принадлежит пути. |
| `usage` | список слов | 0 | `trade` (флаг 0x10) и `patrol` (флаг 0x01), без учёта регистра, любое число значений; остальные слова игнорируются. Применяется к метке пути зоны. |
| `mission_eligible` | bool | false | Могут ли случайные миссии использовать путь. |
| `faction` | - | - | Распознаётся и игнорируется на уровне зоны (значимые строки faction идут после ключа `encounter`, см. ниже). |
| `density` | int | 0 | Максимальное число NPC-кораблей около зоны. |
| `repop_time` | float | 10 | Время репопуляции в секундах; значение 0 или меньше заменяется на 1. |
| `mission_type` | список слов | зона законная | Сбрасывает флаг lawful, затем `lawful` / `unlawful` (без учёта регистра, любое количество) устанавливают соответствующий флаг; если нет ни того, ни другого, зона законная. |
| `vignette_type` | string | 1 | `field` -> 2, `exclusion` -> 4, любой другой текст -> 1 (без учёта регистра). |

Зона **отбрасывается**, если у неё нет `path_label`, она не законная и не незаконная и (при загруженных столкновениях) у неё нет ни одного из ключей популяции ниже.

Ключи популяции (читаются только когда столкновения загружаются; любой из них помечает зону как населённую):

| Ключ | Тип | По умолчанию | Значение |
|---|---|---|---|
| `encounter` | id, float, float | нет | Повторяемый. Значение 0 — id столкновения из `[EncounterParameters]` (неизвестный id **не** проверяется и приводит к сбою), значение 1 — уровень сложности (усекается до int; добавляет класс кораблей `diff<level>` к строкам классов столкновения, см. [ai-and-encounters.md](ai-and-encounters.md#31-encounterformation)), значение 2 — шанс выбора (вес среди столкновений зоны). Каждая строка `encounter` работает со своей копией параметров системы. |
| `faction` (после `encounter`) | string, float | нет | Непосредственно следующие строки `faction = group, weight` поглощаются предшествующим ключом `encounter` (первая строка не-`faction` завершает серию и обрабатывается как обычно). Они задают столкновению веса фракций. |
| `density_restriction` | int, id | нет | Повторяемый; максимальное число (значение 0) кораблей типа (значение 1, хэшированный id), допустимых около зоны. |
| `population_additive` | bool | true | |
| `tradelane_attack` | float | 0 | Вероятность нападения на торговую трассу для зоны, записывается в процентах (хранится делённой на 100). |
| `max_battle_size` | int | 0 | |
| `relief_time` | float | 15 | Принудительно 0, если на этот момент `repop_time` отрицателен. |

## 4. Таблицы кратчайших путей между системами

Три таблицы отвечают на вопрос «сколько прыжков от системы A до системы B»: `Universe\systems_shortest_path.ini` (все соединения), `Universe\shortest_legal_path.ini` (только джамп-гейты) и `Universe\shortest_illegal_path.ini` (только джамп-холы). Их читает `LoadSystemPathTables` ([SystemConnections.cpp:340](../../../src/Content/SystemConnections.cpp#L340)) при `LoadGame`, и обычно они **генерируются самой игрой**. `InitSystemPathTables` ([SystemConnections.cpp:377](../../../src/Content/SystemConnections.cpp#L377)) проверяет, можно ли открыть `systems_shortest_path.ini` по пути Data; если нельзя, таблицы вычисляются по соединениям систем (поиск по соединениям каждой системы с пропуском заблокированных гейтов) и записываются `WriteSystemPathTables` ([:457](../../../src/Content/SystemConnections.cpp#L457)). **Писатель открывает файлы по путям относительно рабочего каталога `..\data\Universe\<name>.ini` (текстовый режим), а не через путь Data**; поэтому место, где они окажутся, зависит от рабочего каталога процесса. Имена систем писатель берёт из `nickname` каждой секции `[System]` файла `Universe\universe.ini` (обрезая до 15 символов).

Формат (каждого из трёх файлов):

```
[SystemConnections]

Path = from_system, to_system, system_1, system_2

```

Одна секция `[SystemConnections]` на систему-источник, одна строка `Path` на пункт назначения ([SystemConnections.cpp:309](../../../src/Content/SystemConnections.cpp#L309)):

| Ключ | Тип | Значение |
|---|---|---|
| `Path` | string, string, strings... | Значение 0 — никнейм системы-источника, значение 1 — никнейм системы назначения, значения 2.. — системы маршрута, каждая разрешается через `GetSystemID`. Длина маршрута — то, что возвращают таблицы. |

Секция хранится под своим последним `from`; секция, чей `from` не разрешается ни в какой id системы, отбрасывается. Строка с любым ключом, кроме `Path`, заставляет загрузчик вставить пустой маршрут для предыдущего пункта назначения (или для системы 0), поэтому других ключей быть не должно. Если таблица отсутствует или пуста, поиск маршрутов ничего не находит. Существование проверяется только у первого из трёх файлов.

## 5. `missions\mBases.ini`

База данных миссионных баз: какие фракции управляют базой, какие миссии предлагает её бар и какие персонажи стоят в её комнатах. Файл читается дважды разными проходами по последовательности групп `[MBase]`:

```
[MBase]
nickname = example_base
local_faction = example_group
diff = 12
msg_id_prefix = example_prefix

[BaseFaction]
faction = example_group
weight = 1.0
mission_type = DestroyMission, 5, 20, 2.0
npc = example_npc

[MVendor]
num_offers = 2, 5

[GF_NPC]
nickname = example_npc
...

[mRoom]
nickname = Bar
fixture = example_npc, placement_name, fidget_script, role
```

* **Проход 1** (`BuildContentBases`, [BaseDB.cpp:415](../../../src/Content/BaseDB.cpp#L415); `FContentBase::LoadFactions`, [:175](../../../src/Content/BaseDB.cpp#L175)): для каждой `[MBase]` первая строка со значением должна быть `nickname` (никнейм базы, разрешается через `GetBaseID`; читается как первая строка независимо от ключа), затем остаток этой секции, затем секции `[BaseFaction]` до следующей `[MBase]`. Другие виды секций пропускаются. Если никнейм не является известной базой, просмотр продолжается, только если следующая секция — другая `[MBase]`; любая другая следующая секция завершает весь просмотр.
* **Проход 2** (`FContentBase::Load`, [:252](../../../src/Content/BaseDB.cpp#L252)): файл открывается снова, находится `[MBase]`, чей `nickname` совпадает (без учёта регистра), и секции `[MVendor]`, `[GF_NPC]` и `[mRoom]` читаются до следующей `[MBase]`. Виды секций, которых проход не знает (`[BaseFaction]`), пропускаются.

### 5.1 `[MBase]` (проход 1, остаток секции после строки nickname)

| Ключ | Тип | По умолчанию | Значение |
|---|---|---|---|
| `local_faction` | string | -1 | Никнейм группы репутации локальной фракции базы. |
| `diff` | int | 10 | Уровень сложности базы. |
| `msg_id_prefix` | string | пусто | Префикс сообщений комма. |

### 5.2 `[BaseFaction]` (проход 1)

| Ключ | Тип | По умолчанию | Значение |
|---|---|---|---|
| `faction` | string | -1 | Никнейм группы репутации. |
| `weight` | float | -1 | Вес выбора среди фракций базы. |
| `mission_type` | string, float, float, [float] | нет | Повторяемый. **Значение 0 не читается** (тип всегда `DestroyMission`); значение 1 — минимальная, значение 2 — максимальная сложность (здесь не ограничиваются); необязательное значение 3 — вес (по умолчанию 1.0). Запись сохраняется, только если установлен флаг сборки для текущего игрового режима; в порте оба флага всегда true. |

### 5.4 `[GF_NPC]` (проход 2, [BaseDB.cpp:55](../../../src/Content/BaseDB.cpp#L55))

Персонаж бара/базы. Хранится под `CreateID(nickname)` (побеждает первое определение). Загрузчик вычисляет, полна ли запись (nickname, тело из `body` или из костюма `base_appr`, голос и `individual_name`), но вызывающий не проверяет результат, поэтому неполные записи тоже сохраняются. ## 6. `missions\news.ini`

Читается `LoadNewsItems` ([BaseSupport.cpp:179](../../../src/Content/BaseSupport.cpp#L179)); каждая секция `[NewsItem]` добавляется в список в порядке файла (проверки на дубликаты нет). Какие новости показывает база, зависит от `base` и `rank`.

| Ключ | Тип | По умолчанию | Значение |
|---|---|---|---|
| `base` | string | нет | Повторяемый; никнейм базы (`GetBaseID`), на которой показывается новость; дубликаты игнорируются. |
| `rank` | string, string | стадии 0-42 | Имена первой и последней стадии миссии (та же таблица из 43 имён, что для слухов), между которыми показывается новость. Неизвестное имя сохраняет предыдущее значение стадии. |
| `breaking` | flag | выкл. | Одного присутствия достаточно, чтобы установить флаг «breaking»; значение не читается. |
| `autoselect` | flag | выкл. | Одного присутствия достаточно, чтобы установить флаг «autoselect». |
| `icon` | string | категория 0 | `critical` (1), `world` (2), `mission` (3), `system` (4), `faction` (5), `universe` (6); другой текст оставляет категорию как есть. |
| `category` | int | нет | Id ресурса шаблона mad-lib, сохраняемого в слоте заголовка новости (только первый параметр). |
| `headline` | int | нет | Id ресурса шаблона mad-lib, сохраняемого в текстовом слоте новости. |
| `text` | int, ints... | нет | Значение 0 — id ресурса mad-lib, следующие значения — id строк, добавляемые к нему (сохраняется в слоте аудиотекста новости). |
| `logo` | string | нет | Имя текстуры логотипа (выделяется один раз; не проверяется). |
| `audio` | string | нет | Имя аудио. |

Три ключа шаблонов сохраняются в перечисленных выше слотах структуры данных порта (имена слотов в порте могут не отражать их роль в игре); имена ключей в точности те, что проверяет код.

## 7. Секции сохранения `[DynBaseInfo]` и `[DynSysInfo]`

При `LoadGame` модуль Content получает ридер на текст сохранения и вызывает `LoadDynBaseInfo` ([BaseDB.cpp:447](../../../src/Content/BaseDB.cpp#L447)) и `LoadDynSysInfo` ([SystemInfo.cpp:2074](../../../src/Content/SystemInfo.cpp#L2074)). Каждая сначала перестраивает всю таблицу баз или систем из вселенной, затем ищет свою секцию. Значение `nickname` секции разрешается и ищется в таблице, но результат отбрасывается: из этих секций никакое динамическое состояние не восстанавливается. Соответствующие функции записи (`SaveContentBases`, `VisitSystemInfos`) обходят свои таблицы с пустыми телами, так что для них тоже ничего не пишется.

| Секция | Ключ | Тип | Значение |
|---|---|---|---|
| `[DynBaseInfo]` | `nickname` | string | Никнейм базы (`GetBaseID`); только первый в секции. |
| `[DynSysInfo]` | `nickname` | string | Никнейм системы (`GetSystemID`); только первый в секции. |

Связанные секции Content того же текста сохранения (`[locked_gates]`, состояние миссий и игрока) описаны в [missions.md](missions.md).
