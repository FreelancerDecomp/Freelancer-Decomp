# INI-файлы данных мира, читаемые Common.dll

В этом документе перечислены INI-подобные файлы, которые сам `Common.dll` разбирает при построении игрового мира: диспетчер `[Data]`, `universe.ini` и системные файлы, на которые он указывает, файлы баз и комнат, списки рынков, костюмы и части тела, шаблоны новых персонажей, очереди fuse и petal, таблица модификаторов оружия, группы репутации, ползунок производительности real-time-катсцен и маршрутизация журнала ошибок. Для каждого файла приведены секции, ключи, типы значений, значения по умолчанию и поведение при повторах — так, как их читает исходный код.

**Расположение файлов / как они находятся.** Каждый файл ниже достигается из секции `[Data]` файла `freelancer.ini` (см. [freelancer-ini.md](freelancer-ini.md)), кроме `[Error]`, который находится в самом `freelancer.ini`. `DataConfig::startup` обходит `[Data]` в порядке файла и для каждого известного ключа разрешает значение через `GetFileSysPath(..., nullptr)` (относительное значение присоединяется к корню файловой системы `[Freelancer] data path`, значение, начинающееся с `\` или имеющее `:` вторым символом, используется как есть). Большинство файлов в retail-данных — BINI, в модах — обычный текст; `INI_Reader` принимает оба формата (см. [parsers.md](parsers.md)). Имена ключей и секций сравниваются без учёта регистра. Ключ, встречающийся дважды, доставляется дважды, в порядке файла; каждый читатель ниже указывает, переопределяет ли более позднее значение предыдущее, игнорируется или добавляется. «Не проверяется» означает, что код не применяет никакой проверки диапазона или перечисления.

Соглашения в таблицах: `id` = текст, хэшированный через `CreateID` (32-битный хэш nickname); `MakeId` = 16-битный хэш, используемый для имён фракций/групп; «всё значение» = `get_value_string()` без индекса, т. е. все параметры, разделённые запятыми, склеенные вместе (запятые включены); `[n]` = параметр номер n, разделённый запятыми (`get_value_*(n)`), счёт с 0.

Примеры в этом документе синтетические и не скопированы из игровых данных.

## 1. Диспетчер `[Data]` (`DataConfig`)

`DataConfig::startup(IniPath, Factory, Progress)` открывает `freelancer.ini` (путь передаёт вызывающий), читает каждую найденную секцию `[Data]` (допускается несколько), и для каждого ключа по порядку при необходимости вызывает прикладной callback прогресса с всем значением (ненулевой ответ прерывает загрузку), затем выполняет диспетчеризацию. Неизвестные ключи игнорируются (у клиента есть второй диспетчер для ключей UI/эффектов, см. [client-world-fx.md](client-world-fx.md) и [client-ui-config.md](client-ui-config.md)). После этого загружается `AI\state_graph.db` (бинарный файл, не INI). Повторный вызов `startup` лишь увеличивает счётчик ссылок и возвращается.

Поскольку ключи обрабатываются в порядке файла, порядок важен: `universe` должен предшествовать `bases` (список баз строится из баз вселенной), а `goods` и `bases` — предшествовать `markets` (строки рынка при загрузке ищут nickname товаров и баз).

## 2. `universe.ini` и системные файлы (`Universe`)

`Universe::Startup(path)` считает ссылки: файл разбирается, только когда счётчик равен нулю. Он разрешает `path` относительно пути данных, создаёт DOS-файловую систему с корнем в каталоге `universe.ini` («каталог вселенной»), затем разбирает файл. Ноль систем после разбора пишет в журнал "could not create universe". Таблицы вселенной (системы, базы, зоны, врата) очищаются перед каждой настоящей загрузкой.

Имена заголовков, проверяемые при обходе `universe.ini`: `Time`, `System`, `Base`. Любой другой заголовок молча пропускается.

### 2.4 Системный файл (`Systems\Xx01\Xx01.ini`, как его читает Common)

`LoadSystemFile` открывает файл, названный в `[System] file =`, и делает три прохода:

1. каждая секция `[Object]` читается для таблицы «vibe» репутации (`LoadObjectVibesFromSystemIni`, таблица ниже);
2. читатель перематывается, и секции `[Zone]`, `[Music]` и `[Object]` читаются для данных вселенной;
3. прочие заголовки Common игнорирует (они принадлежат серверу, модулю Content и клиенту, см. [systems-and-bases.md](systems-and-bases.md)).

## 3. Файлы баз (`BaseData`)

Один файл на базу вселенной, называется значением `[Base] file =` в `universe.ini` и разрешается относительно пути данных. База с пустым `file` сообщается как ошибка. Если файл не удаётся открыть, в журнал пишется ошибка с разрешённым путём. Заголовки, кроме `Base`/`BaseInfo`/`Room`, пишут в журнал "Invalid ini block".

**`[Base]` или `[BaseInfo]`** (`read_Base_block`). Неизвестные ключи пишут в журнал "Invalid ini data" (блок всё равно обрабатывается).

## 8. База petal (`[Data] PetalDB`)

`PetalInterfaceDatabase::load_from_ini`. Неоткрываемый файл пишет ошибку в журнал. Читается только заголовок `ObjectTable`; остальные заголовки пропускаются. ## 9. Группы репутации (`[Data] Groups`, `InitialWorld.ini`)

`Reputation::Startup(path)` читает из текстового файла `InitialWorld.ini` только *определения* групп (он же — затравка новой игры, см. [saves-and-initial-world.md](saves-and-initial-world.md)). Читаются только заголовки `[Group]`; остальные заголовки игнорируются. Блок разбирается **по позиции, а не по имени ключа**, за исключением двух проверок:

1. первая строка со значением, каким бы ни был её ключ, — nickname группы (до 15 символов; id = `MakeId(nickname)`);
2. вторая строка со значением, каким бы ни был её ключ, — `ids_name` (`[0]`, целое);
3. третья строка со значением — `ids_info`, если её ключ `ids_info`, иначе `ids_info = 0` (строка потребляется в любом случае);
4. четвёртая строка со значением — `ids_short_name`, если её ключ `ids_short_name`, иначе 0.

| Позиция | Ожидаемый ключ | Тип | По умолчанию | Значение | Источник |
|---|---|---|---|---|---|
| 1 | `nickname` | строка (<= 15 символов) | пусто | nickname группы; хэшируется 16-битным `MakeId`. Группа с уже присутствующим id повторно использует существующую запись. | [common_reputation.cpp](../../../src/Common/common_reputation.cpp#L118) |
| 2 | `ids_name` | int | н/д | `[0]`, усекается из float. | то же |
| 3 | `ids_info` | int | 0 | `[0]`. | то же |
| 4 | `ids_short_name` | int | 0 | `[0]`. | то же |

Остальные строки блока (например, `rep`) `Startup` игнорирует. Строки `rep` позже читает `Reputation::LoadFeelings` при загрузке сохранения или начального мира (вызывается загрузчиком сервера с уже открытым читателем):

| Ключ | Тип | По умолчанию | Значение | Источник |
|---|---|---|---|---|
| `rep` | float, nickname | нет | Повторяемый `rep = value, other_group`: отношение группы к `other_group` (`MakeId`). Уже присутствующая пара сохраняет первое значение. Блок `[Group]` без строки `rep` пишет в журнал "save game has corrupted reputation data"; имя группы, не совпадающее ни с одной загруженной группой, пропускает свои строки. | [common_reputation.cpp](../../../src/Common/common_reputation.cpp#L208) |

Сохранение пишет блок той же формы (`nickname`, затем по одной `rep = <value>, <group>` на каждое отношение) через писатель сохранений.

## 10. Файлы fuse (`[Data] fuses`)

Сервер (`ServerFuseDB::LoadFile`) и клиент (`ClientFuseDB::LoadFile`) позже открывают каждый файл из очереди; определяемые ими действия описаны в [server.md](server.md) и [client-world-fx.md](client-world-fx.md). ## 12. Ползунок производительности real-time-катсцен (`[Data] RtcSlider`)

`RtcSlider::load(path)`. Неоткрываемый файл пишет ошибку в журнал. Заголовок, отличный от `RtcSlider`, пишет предупреждение и пропускается. Строка со значением, ключ которой не `set` и не `set_less`, пишет предупреждение.

| Ключ | Тип | По умолчанию | Значение / допустимые значения | Источник |
|---|---|---|---|---|
| `set` | имя, float | нет | Повторяемый `set = feature, threshold`. Оба параметра обязательны (иначе предупреждение, строка игнорируется). Возможность включена, когда значение ползунка больше или равно порогу. Побеждает первое определение имени. | [common_rtcslider.cpp](../../../src/Common/common_rtcslider.cpp#L59) |
| `set_less` | имя, float | нет | Как `set`, но возможность включена, когда значение ползунка строго меньше порога. | то же |

Имя возможности без записи сообщается как предупреждение во время запроса и считается включённым. `fps_20_cap` и `fps_30_cap` ищутся по имени для ограничения частоты кадров (20 fps, затем 30 fps, иначе 200). Файлы комнат могут ссылаться на имена настроек как на приоритеты (раздел 5); существование имени не проверяется.

## 13. Маршрутизация журнала `[Error]` (`freelancer.ini`)

`ErrorHandler::activate(ini_path, assertHandler)` устанавливает диагностический hook дампа и читает секцию `Error` файла `freelancer.ini` клиента (клиент вызывает его из `WinMain` сразу после стартовой конфигурации; сервер не вызывает). Отсутствие файла или секции просто не оставляет каналов журнала. Читается только ключ `log`.

| Ключ | Тип | По умолчанию | Значение / допустимые значения | Источник |
|---|---|---|---|---|
| `log` | список | нет | Повторяемый `log = where[, kind[, severity]]`, один канал журнала на строку (каналы добавляются в начало списка, кроме каналов `$Window`, которые добавляются в конец). `[0]` where: `$Text` (вывод отладчика), `$Window` (окно сообщения, имена с `$` сравниваются без учёта регистра) или любой другой текст = имя файла, открывается с `"wb"` (усекается). Длиннее 127 символов обрезается. `[1]` kind, по умолчанию -1 (все виды): число или символ в кавычках, например `'c'` (символьные литералы принимаются разборщиком чисел); сравнивается с флагами сообщения, сдвинутыми вправо на 4. `[2]` предел серьёзности, по умолчанию 100: сообщения, серьёзность которых (младший полубайт флагов сообщения; 1 = ошибка, 2 = предупреждение, 3 = уведомление в используемых кодом флагах) численно выше предела, отбрасываются. Ни `[1]`, ни `[2]` не проверяются. Канал, который не удаётся активировать (файл не открывается), отбрасывается. | [common_errorhandler.cpp](../../../src/Common/common_errorhandler.cpp#L381) |

Пример (синтетический):

```ini
[Error]
log = messages.log, -1
log = $Window, -1, 1
log = $Text, 65536, 5
```

Помимо `[Error]`, клиент после чтения секции открывает один дополнительный фиксированный канал `FLSpew.txt` в пользовательской локальной папке данных (kind -1, серьёзность 7) ([main.cpp](../../../src/freelancer/Client/main.cpp#L661)).

## 14. Ключи в dev `bin\freelancer.ini` и то, что читает Common

Dev-секция `[Data]` содержит также ключи, которые диспетчер Common **не** обрабатывает (`effects`, `effect_shapes`, `intro`, `gate_tunnels`, `HUD`, `jump_effect`, `igraph`); они принадлежат диспетчеру клиента. Ключи, которые Common обрабатывает и которые есть в dev-файле: `universe`, `constants`, `equipment`, `solar`, `ships`, `asteroids`, `explosions`, `loadouts`, `bodyparts`, `costumes`, `bases`, `goods`, `markets`, `PetalDB`, `groups`, `fuses`, `WeaponModDB`, `NewCharDB`, `rtcslider`. Dev-секция `[Error]` содержит только строки `log`.
