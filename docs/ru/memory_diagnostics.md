# Поиск утечек памяти (`MemoryDiagnostics`)

Проект `MemoryDiagnostics` в `src/Freelancer.sln` собирает небольшую Win32-утилиту
`MemoryDiagnostics.exe`, которая управляет UMDH (User-Mode Dump Heap) для поиска утечек в куче
Windows игры. Код самой игры не инструментируется.

## Требования

**Debugging Tools for Windows** из Windows SDK. Утилита ищет папку `Debuggers/x86`, содержащую
`gflags.exe` и `umdh.exe`; путь к ней можно указать вручную.

## Порядок работы

1. Выберите обычный Debug-клиент в `bin`, папку для логов и, при необходимости, путь к символам.
2. Нажмите **Enable stack tracing**, затем **Launch game**. Windows запрашивает повышение прав
   только для GFlags. Флаг привязан к имени EXE и действует на каждый новый процесс с этим именем;
   уже запущенную игру нужно перезапустить.
3. После того как сценарий «прогрелся», нажмите **Take snapshot**. Повторите действие, вернитесь
   в исходное состояние и сделайте ещё один снимок.
4. Выберите два снимка с помощью Ctrl/Shift и нажмите **Compare pair**; текстовый отчёт откроется
   автоматически. Стек, который растёт от сравнения к сравнению, — кандидат на утечку: проверьте
   владение этими объектами и их освобождение.
5. По окончании нажмите **Disable stack tracing**. Закрытие утилиты не сбрасывает сохранённый
   флаг и не закрывает игру.

Снимки разделяются по идентификатору процесса и времени его создания. **Attach to game** находит
уже запущенный процесс по полному пути; при нескольких экземплярах укажите PID. При таком
подключении неизвестно, в каком режиме трассировки процесс был запущен.

## Подробности

- Логи по умолчанию пишутся в `D:/Temp/FreelancerLeaks`. Символы берутся из настроенного
  `_NT_SYMBOL_PATH` (кэш по умолчанию `J:/pdb_cache`). Поле принимает синтаксис WinDbg
  (`cache*`, `srv*`, папки через `;`). PDB рядом с EXE подхватываются автоматически и должны
  соответствовать запущенной сборке. Флажок **Windows symbols** можно снять, чтобы сравнивать по
  локальным PDB и уже закэшированным символам без загрузки.
- Утилита запускает игру с `OANOCACHE=1`, чтобы отключить кэш BSTR.
- Вывод и ошибки UMDH пишутся рядом со снимком как `.tool.txt`; незавершённые снимки сохраняют
  суффикс `.pending` и при сравнении игнорируются.
- UMDH анализирует только кучу Windows. Для приватных пулов, `VirtualAlloc` и видеопамяти нужны
  другие инструменты. `DebugASan` хорош для порчи памяти, но его собственное удержание памяти
  искажает измерение утечек.

См. [руководство по UMDH](https://learn.microsoft.com/en-us/windows-hardware/drivers/debugger/using-umdh-to-find-a-user-mode-memory-leak).
