# alchemy.dll — система эффектов

Модуль создаёт и обновляет графы эффектов, хранит прототипы нод и архетипы,
управляет пулами частиц и передаёт геометрию render pipeline.
Исходники находятся в `src/alchemy/`, публичные типы — в
[`src/include/alchemy.h`](../../../src/include/alchemy.h).

Источник поведения — `EXE/Disasm/alchemy.dll.txt`, при усечённых операндах —
исходный PE `EXE/alchemy.dll`. Здесь описаны архитектура и форматы; статусы,
адресные доказательства, слоты, source mappings и конкретные пробелы хранятся
в decomp-tracker. Общий долг — [deviations.md](deviations.md), правила контрактов —
[cross_dll_protocol.md](cross_dll_protocol.md).

## Загрузка и общие состояния

DACOM загружает наш `bin/alchemy.dll`; retail DLL служит только RE-эталоном.
Возврата к retail DLL при ошибке загрузки нет. PE не публикует экспортов;
компоненты доступны через регистрацию фабрик DACOM.

Порядок process attach: запрет thread notifications, выбор CPU/math dispatch,
регистрация Alchemy и FxRuntime, чтение `[Alchemy]`, создание восьми appearance
пулов, затем регистрация остальных компонентов. INI-парсер встроен в dacom и
получается через `IProfileParser`; luaprofile в этой цепочке не участвует.
Отдельный Initialize Alchemy получает интерфейсы pipeline и связывает начальную
ноду. Перенос INI и пулов в Initialize меняет порядок побочных эффектов.

Process detach освобождает пулы в порядке Oriented, Mesh, Rect, Perp, Particle,
Basic, Dust, Beam. Очистка pipeline, эффектов и отрисовки имеет собственных
владельцев; её нельзя добавлять к DLL detach только ради удобства.

Callbacks, runtime bindings, pipeline cache, draw flags и batch lists принадлежат
DLL, а не отдельному экземпляру Alchemy. Независимые binding-параметры сохраняют
независимые значения, даже если один вызывающий передаёт одинаковые указатели.
Изменение владения требует трассировки всех producers, consumers и teardown.

Локальные кеши 3DMath сохраняют самостоятельное состояние: одинаковое имя сервиса
не доказывает, что можно объединить экземпляры и изменить число CreateInstance.
Чтения кешей, наборов свойств и связей после внешнего callback должны брать
текущее значение. Владеющая ссылка и заимствованный кеш набора могут обновляться
в разные моменты одной операции; выводить кеш из владельца допустимо только
после доказательства этого порядка по всем соответствующим путям.

Alchemy и FxRuntime имеют внутренний unknown со своим счётчиком ссылок и
ссылкой на владельца. Публичные грани делегируют QI/AddRef/Release контролирующему
outer; у самостоятельного объекта эту роль выполняет собственный inner.
Дескриптор агрегации использует общий тип из `dacom.h`. Дескриптор создания
FxEffect имеет отдельный контракт: архетип и корневой родитель.

Binding библиотеки эффектов хранит отдельно `IAlchemy*` для операций с деревом
и `IFxNodeLibrary*` для поиска прототипа. Общий интерфейс библиотеки нод объявлен
в публичном заголовке и является базой `IAlchemy`. Загрузка и сохранение принимают
`IFileSystem*`; chunk использует файловый дескриптор из `readfile.h`.

## Объектная модель

Библиотека нод связывает хеш имени экземпляра с прототипом. Создание из прототипа
идёт через его CloneNode; имя экземпляра не является именем DACOM-фабрики.
Библиотека эффектов связывает ключ с архетипом. CreateEffect получает готовый
32-битный ключ; дополнительный поиск по имени с другим хешем меняет контракт.
Хеш имён использует таблицу Alchemy/DACOM CRC без приведения регистра.

Загрузчик нод, библиотека нод и библиотека эффектов имеют независимые статические
буферы разрешённых имён. Возвращённая заимствованная строка сохраняется до следующей
генерации в том же буфере; вызов соседнего генератора её не перезаписывает.

Обе библиотеки хранят владеющий map по хешу и отдельную цепочку порядка вставки.
Обход и сохранение идут по цепочке; после callback читается текущая связь Next.
Очистка сначала размыкает цепочку, затем освобождает map в обратном порядке ключей.

Архетип хранит записи нод и пары ассоциаций. Экземпляр эффекта создаёт/клонирует
ноды, связывает родителей и sibling lists, затем emitter с appearance и appearance
с полями. Связи имеют собственное владение ссылками. Одинаковое числовое смещение
слота на разных facets не означает один метод.

В экземпляре эффекта корневые записи образуют отдельный префикс, упорядоченный
по ключу сортировки ноды. Число корней отличается от общего числа записей.
Связанные поля appearance имеют отдельные публичные методы count/Out и index/Out;
внутренний обход использует заимствованные ссылки.

Нода и набор её свойств — разные объекты и интерфейсы. Typed property sets
содержат значения и настоящие ramp/animation objects; таблицы класса описывают
имена, хеши, виды и границы свойств. Enumeration сначала проходит базовый набор,
затем набор конкретного класса и сохраняет callback short-circuit. Общая сумка
неизвестных значений не заменяет этот протокол.

Private C++ классы и контейнеры используют современный CRT/STL. Их бинарная
раскладка не обязана воспроизводить VC6. Межмодульный интерфейс объявляется один
раз в общем заголовке; известный тип сохраняется у вызывающего и получателя.

## Форматы ALE

В UTF-контейнере каталоги `ALEffectLib` и `AlchemyNodeLibrary` содержат одноимённые
data leaves. Сначала вход в каталог, затем открытие leaf изнутри него.
На обычном выходе библиотека переходит в `..` перед закрытием chunk.
Ошибочные выходы имеют собственный порядок cleanup. Переданный FileSystem
обслуживает всю операцию, включая ошибки и cleanup.

`ALEffectLib` начинается с float версии и signed count эффектов. Запись эффекта
содержит имя, для версии 1.1 — дополнительный Header16, затем count и массив
16-байтных записей нод, count и массив 8-байтных ассоциаций. Публичные
`FAleRec16`/`FAleRec8` описывают значения записей: ID, связи и ключи прототипов.
Перестановка полей между file storage и accessor API должна сохраняться.

Строка: uint16 длины с NUL, затем байты; нечётная длина дополняется одним padding
byte. Числовые поля little-endian.

Поток свойств ноды: uint16 Type; ноль завершает запись, иначе следует uint32 Hash
и payload. `Kind = Type & 0x7fff`; старший бит bool-типа кодирует значение без
дополнительных байтов.

| Kind | Payload |
|------|---------|
| 1 | Bool в старшем бите Type |
| 2, 3 | Четыре байта scalar value |
| 0x100, 0x101 | Режим, число ключей, scalar/color ramp keys |
| 0x102 | AnimatedSingle track |
| 0x103 | Строка с длиной и padding |
| 0x104 | Пара 32-битных значений |
| 0x105 | AnimatedTransform и его вложенные tracks |
| 0x200–0x202 | Вложенные ramp/animation данные, зависящие от версии |

Legacy remap хешей и видов применяется перед выбором typed accessor. Неизвестный
тип имеет путь ошибки; нельзя угадывать размер payload и продолжать чтение.
Short-read, reset, mutation order и exception cleanup являются частью формата.
Загрузка читает chunk напрямую: Reset, setters и добавление ключей чередуются
с файловыми чтениями. Временные target/child ссылки освобождаются на обычных
выходах и коротком чтении; очистка при исключениях соответствует EH-цепочке retail.

## Пулы, симуляция и отрисовка

Basic, Particle, Rect, Perp, Mesh, Oriented, Dust и Beam имеют отдельные пулы.
Пул владеет item storage, free/used lists и счётчиками. Spawn, reclaim, unlink,
повторное создание и teardown сохраняют владельца записи. Дополнительные
COM-объекты в Mesh/Particle item освобождаются по собственному контракту;
factory pointer и созданный объект нельзя смешивать.

Выдача и возврат памяти пула не освобождают COM-ссылки записи. Eraser сначала
размыкает список и выполняет очистку объектов записи, затем возвращает память
пулу. Временные владельцы этих ссылок сохраняют порядок очистки при исключении
из callback. Память самого COM-объекта освобождается после успешного деструктора.

Emitter вычисляет частоту и число новых items; appearance применяет поля,
интеграцию и свои transform/rotation rules. Begin/Apply/End полей и порядок
ramp evaluation остаются частью графа. Math dispatch проверяется по фактическим
consumers, а не по общему названию «x87».

Малые численные операции вынесены в `alchemy_math.cpp`, который во всех
конфигурациях собирается с `/O2 /Oi /fp:fast /arch:IA32`. Это позволяет получить
прямые x87-инструкции и единственное конечное сохранение `float` средствами C++;
остальная арифметика сохраняет точный режим вычислений проекта. Преобразование
в целое временно меняет только округление x87 на усечение и восстанавливает его
после успешного преобразования, оставляя MXCSR без изменений.

BeginDraw/EndDraw управляют draw protocol, VB recovery, сохранением/восстановлением
render states, четырьмя batch lists и counters. Материальный state block задаёт
render states и texture-stage states; это не vertex-format declaration.
Ошибка создания буфера не даёт права добавлять повторный SelectVB или менять
InDraw иначе, чем в retail.

Appearance формирует геометрию своей разновидности; Mesh получает создаваемый
клиентом объект через публичный `IFxMeshFactory`. Камера, текстуры и pipeline —
межмодульные контракты. Null fallback или приблизительная геометрия не считаются
эквивалентом retail пути.
