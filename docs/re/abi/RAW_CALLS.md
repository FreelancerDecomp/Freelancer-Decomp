# Вызовы через сырой номер слота (`Vtable[N]`)

Сгенерировано `tools/abi.py build` — руками не править.

`reinterpret_cast<FnX>(Vtable[0x1C / 4])(Obj, ...)` — вызов, который компилятор не проверяет **никак**: ни число аргументов, ни типы, ни соглашение вызова. Каждая такая строка заново изобретает сигнатуру чужого метода. Это прямое следствие того, что интерфейс не выведен в паблик — см. [../cross_dll_protocol.md](../cross_dll_protocol.md) и [AUDIT.md](AUDIT.md).

Всего: **0** вызовов.

## Один объект + один слот, разные сигнатуры

**Кандидаты в баги, а не приговор**: одинаковое имя переменной ещё не значит одинаковый интерфейс (в одном файле `Ctrl` может быть двумя разными объектами). Но если это правда один интерфейс — один из вызовов кладёт в стек не то, что забирает `__stdcall`-получатель.

Не найдено.
